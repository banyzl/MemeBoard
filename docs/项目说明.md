# MemeBoard：Raycast × 万象拼音本地表情包输入系统

## 0. 项目目标

为 macOS 开发一套本地表情包管理与快速输入系统，主要服务于 QQ 等聊天软件。

系统包含两个主要入口：

1. **Raycast**
    
    - 添加图片
        
    - 为图片命名
        
    - 添加别名、标签和快捷码
        
    - 以图片 Grid 形式浏览
        
    - 搜索图片
        
    - 选择图片后直接粘贴到当前聊天输入框
        
2. **Rime / 鼠须管 / 万象拼音**
    
    - 在正常拼音输入过程中识别图片名称
        
    - 使用类似万象 Super Tips 的方式显示：  
        `〔🖼️ 猫猫无语〕`
        
    - 支持显式快捷码，如：  
        `mmwy`
        
    - 用户按指定快捷键后，将对应图片粘贴进 QQ，而不是提交文字
        

第一版只实现**本地图片 + 本地搜索**。

不要实现：

- AI 识图
    
- Embedding
    
- 在线搜索
    
- 云同步
    
- 多设备同步
    
- Windows 支持
    

但数据模型和搜索层不要阻碍未来增加这些功能。

# 1. 最终用户体验

## 1.1 Raycast 搜索方式

用户设置一个全局快捷键，例如：

`⌥E`

打开 MemeBoard。

界面使用 Raycast `Grid`：

```
┌────────────────────────────────────────────┐
│ 🔍 搜索表情包                              │
├────────────────────────────────────────────┤
│                                            │
│ [ 图片 ]  [ 图片 ]  [ 图片 ]  [ 图片 ]    │
│ 猫猫无语   熊猫无语   绷不住了   看傻了    │
│                                            │
│ [ 图片 ]  [ 图片 ]  [ 图片 ]  [ 图片 ]    │
│ ...                                        │
└────────────────────────────────────────────┘
```

默认建议：

- 5 列
    
- 1:1 单元格
    
- `fit = contain`
    
- 图片下显示名称
    
- 支持 Quick Look
    

用户输入：

`无语`

应能搜索：

- 名称
    
- alias
    
- tag
    
- trigger
    

例如：

```
名称：猫猫无语
aliases：无语猫、沉默猫
tags：猫、无语、沉默
triggers：maomaowuyu、mmwy
```

输入以下任意内容都应该能够找到：

```
猫
无语
沉默
无语猫
mmwy
maomaowuyu
```

V1 优先使用 Raycast 自带 fuzzy filtering。

# 2. Rime 输入体验

存在图片：

```
名称：猫猫无语
```

## 情况 A：根据候选词识别

用户输入：

```
maomaowu...
```

只要当前高亮候选已经变成：

```
猫猫无语
```

就在原有 Rime Prompt 区域显示：

```
〔🖼️ 猫猫无语〕
```

即使用户尚未完整输入：

```
maomaowuyu
```

也应该可以出现。

行为应尽量模仿万象原生 Super Tips：

第一页：

```
当前完整 raw input
        ↓
当前高亮候选文本
```

后续候选页：

```
当前高亮候选文本
```

---

## 情况 B：显式 trigger

每张图片至少拥有一个保证唯一的 trigger。

例如：

```
maomaowuyu
```

可以另外设置：

```
mmwy
```

用户直接输入：

```
mmwy
```

即使“猫猫无语”不在第一候选，也应出现：

```
〔🖼️ 猫猫无语〕
```

这是因为该情况直接匹配 raw input。

# 3. Rime 发送图片

当当前存在 MemeBoard 图片提示：

```
〔🖼️ 猫猫无语〕
```

按图片发送键：

```
meme_key
```

应执行：

```
识别当前图片 ID
        ↓
清除当前 Rime composition
        ↓
调用 MemeBoard Helper
        ↓
Helper 找到对应图片
        ↓
写入 macOS Pasteboard
        ↓
向当前前台 App 执行粘贴
        ↓
QQ 输入框出现图片
```

不能提交：

```
🖼️ 猫猫无语
```

这几个文字。

# 4. 与原版 Super Tips 的兼容原则

这是强制要求。

**不要直接修改万象官方 Super Tips 的核心数据文件。**

不要把图片记录简单塞进：

```
tips_show.txt
```

然后要求用户每添加一张图片就重新部署 Rime。

MemeBoard 必须支持：

```
Raycast 添加图片
      ↓
更新 MemeBoard Rime index
      ↓
Rime 自动发现
```

目标：

**不需要重新部署鼠须管。**

## 4.1 Super Tips Prompt 冲突处理

当前万象已有：

```
〔Emoji：😂〕
〔翻译：hello〕
〔化学式：H₂O〕
```

MemeBoard 不得破坏这些功能。

优先设计为独立：

```
meme_tips.lua
```

并读取已有：

```
segment.prompt
```

若当前同时存在官方 Super Tips 与图片 Tips，可表现为：

```
〔原 Super Tips〕 〔🖼️ 猫猫无语〕
```

若只有图片：

```
〔🖼️ 猫猫无语〕
```

不要修改普通候选排序。

# 5. 图片发送键设计

首先检查当前万象 `super_tips.lua` 的实际 processor 生命周期和按键处理顺序。

目标优先级：

### 首选

图片也使用：

```
comma
```

即用户看到：

```
〔🖼️ 猫猫无语〕
```

按：

`,`

发送图片。

但是必须保证：

- 不破坏原有 Super Tips comma 上屏
    
- 不出现“显示图片 Tips，实际提交普通 Tips”的情况
    
- 不出现两个 processor 同时抢按键
    

### 如果无法干净共存

不要强行 hack。

改为单独可配置：

```
meme_key
```

默认建议：

```
semicolon
```

此时：

```
,
→ 原版 Super Tips

;
→ MemeBoard 图片
```

最终必须把该按键写入配置，而不是硬编码。

## 7.2 Rime Module

建议：

```
meme_tips.lua
```

负责：

- 加载 `meme_index.tsv`
    
- 根据 raw input 查询 trigger
    
- 根据当前高亮候选查询图片 name
    
- 设置/追加 `segment.prompt`
    
- 保存当前 active meme ID
    
- 处理 meme_key
    
- 调用 helper
    

不负责：

- 图片管理
    
- JSON 数据库
    
- 图片搜索
    
- 图片解码

## 7.3 Native Helper

建议使用：

```
Swift
```

构建一个极小 CLI：

```
memeboard-helper
```

接口例如：

```
memeboard-helper paste <UUID>
```

职责：

1. 根据 UUID 找到图片
    
2. 写入 macOS NSPasteboard
    
3. 将图片粘贴到前台应用
    
4. 立即退出
    

Helper 不应显示 Dock 图标，不应抢前台焦点。

**primary name 必须唯一。**

```

```

Rime 的：


必须是确定的一对一关系。

如果冲突，添加界面提示用户重新命名。

# 12. Trigger

每张图片至少存在一个唯一 trigger。

中文名称保存时自动生成完整拼音：

```
猫猫无语
→
maomaowuyu
```

完整拼音作为默认保证 trigger。

同时可以自动建议首字母：

```
mmwy
```

但只有在没有冲突时才能加入。

用户可以手工添加：

```
wymao
```

所有 trigger 全局唯一。

如果冲突：

```
mmwy 已被「猫猫无语2」使用
```

必须阻止保存或要求修改。

禁止自动静默覆盖。

```
无语猫
沉默猫
```

Tag：

```
猫
无语

尴尬
```

只用于搜索和未来语义系统。

# 14. Rime Index 格式

不要让 Lua 解析完整 JSON。

Raycast 根据数据库生成：

```
~/Library/Rime/memeboard/index.tsv
```

格式：

```
T<TAB>maomaowuyu<TAB>UUID<TAB>猫猫无语
T<TAB>mmwy<TAB>UUID<TAB>猫猫无语
N<TAB>猫猫无语<TAB>UUID<TAB>猫猫无语
```

其中：

```
T = trigger
N = name
```

Lua 加载后构造：

```
trigger_map["mmwy"] = {
  id = "...",
  name = "猫猫无语"
}

name_map["猫猫无语"] = {
  id = "...",
  name = "猫猫无语"
}
```

---

# 15. 热更新

添加图片后不得要求 Rime redeploy。

Raycast 每次修改数据库：

1. atomic write `database.json`
    
2. atomic write `index.tsv`
    
3. 更新：
    

```
version
```

例如：

```
27
```

Lua 定期检查：

```
~/Library/Rime/memeboard/version
```

不要每敲一个键完整读取整个 index。

建议：

- 内存缓存 index
    
- 最多每 1 秒检查一次 version
    
- version 变化才 reload
    
- reload 失败继续使用旧缓存
    

目标：

Raycast 保存图片后 **1～2 秒内**可被 Rime 使用。

---

# 16. Atomic Write

所有关键数据写入必须：

```
写临时文件
    ↓
fsync / close
    ↓
rename
```

例如：

```
database.json.tmp
→
database.json
```

避免 Rime 正在读取时遇到半个文件。

---

# 17. Rime 匹配算法

当前每次输入变化时：

## 第一页

```
1. raw input 是否命中 trigger_map
2. 当前 highlighted candidate.text 是否命中 name_map
```

优先：

```
trigger > candidate name
```

## 后续页

只：

```
highlighted candidate.text → name_map
```

尽量保持与当前万象 Super Tips 习惯一致。

---

# 18. Active Meme

Lua 必须保存当前真正显示的图片：

```
active_meme = {
    id = "...",
    name = "猫猫无语"
}
```

只有当：

```
active_meme != nil
```

且用户按：

```
meme_key
```

才允许拦截按键。

否则：

```
kNoop
```

让原 Rime 行为继续。

绝对不能全局吞掉：

```
,
;
```

之类的按键。

# 28. Rime → Helper 技术验证

这是 **P0 第二个 Spike**。

```

→ 显示测试 prompt
```

4. 当前聊天 App 是否保持焦点

```

        ↓

        ↓

```

不要一开始就做常驻进程。

```
interface MemeSearchProvider {

```

V1：


未来可以增加：
